# ミライHD 社内ポータル

東証プライム上場の大企業（架空：株式会社ミライホールディングス）の社内ポータルと業務Webアプリ。
Next.js 16 + Tailwind v4。PC・スマホ（PWA）対応。ログイン + セキュリティコード（TOTP）、勤怠の自動計算つき。

## 2つの動かし方

| モード | 認証 | データ | 用途 |
|---|---|---|---|
| **デモ（static）** | デモ認証（パスワード固定・コード画面表示） | 各端末のブラウザ内 | GitHub Pages で公開・見せる用。`/portal/` で公開 |
| **サーバー（server）** | 社員番号 + パスワード（scrypt）+ 認証アプリのTOTP、5回失敗で15分ロック、CSRF対策、12時間セッション | サーバー上の `data/db.json`。PCとスマホで同期 | 社内LANで実際に使う |

### サーバーモード（同じネットワークのスマホからも勤怠を確認）

```bash
cd portal
npm install
npm run build
npm run start:lan        # 0.0.0.0 で待ち受け、LANのURLを表示（例: http://192.168.1.20:3000）
```

1. PCでもスマホでも、表示されたURLをブラウザで開く（同じWi-Fi/社内LAN）
2. 社員番号（例 `E1012`）と初期パスワード（既定 `Mirai-2026!`。`PORTAL_INITIAL_PASSWORD` で変更可）でログイン
3. 初回のみ QR を認証アプリ（Google/Microsoft Authenticator 等）で読み取り、6桁コードを入力
4. 初期パスワードの変更を求められます（12文字以上・英字/数字/記号）

外出先から使う場合は、社内VPN（または Tailscale 等）経由で同じURLに接続してください。**インターネットへ直接公開しないでください。**
ホーム画面へのインストール（PWA）は https が必要な端末があります（リバースプロキシで https 化）。

環境変数: `PORTAL_DATA_DIR`（データ保存先）, `PORTAL_INITIAL_PASSWORD`, `PORTAL_SESSION_SECRET`（複数台構成時のみ）。

### デモ（GitHub Pages）

`main` へのマージで `.github/workflows/lp.yml` が LP と一緒にビルドし、`/portal/` に公開します（Settings → Pages → Source: GitHub Actions）。
手元で確認: `NEXT_PUBLIC_BASE_PATH= npm run build:static` → `out/`。ログイン画面に社員番号とパスワード、当日のデモ用コードが表示されます。

| 画面 | 内容 |
|---|---|
| ログイン | 社員番号 + パスワード + セキュリティコード（RFC 6238 TOTP、QR登録）、無操作30分で自動ログアウト |

| ワークフロー | 経費・休暇（土日祝除外で日数自動計算）・出張・稟議・IT申請。所属長と金額に応じた承認ルート自動生成 |
| お知らせ / 名簿・組織図 / 文書 / 会議室 / ヘルプデスク / 研修 / 監査ログ | 前バージョンと同様 |

## 5W1H（いつ・どこで・誰が・何を・なぜ・どのように）を勤怠と承認に組み込み

別タブではなく、**日々の入力そのもの**に 5W1H を組み込んでいます。

- **勤怠（打刻）**: 出勤前でも打刻後でも、打刻カードで「何を／なぜ／どのように／誰と」を入力（どこで＝勤務場所、いつ＝打刻時刻は自動）。入力は自動保存され、退勤前に書き足せます。
- **勤怠（日別）**: 勤務実績の各行を開くと、その日の5W1H（6項目の完成度つき）と「行動メモ」（商談・移動・作業など）を確認・追加できます。打刻修正でも5W1Hを編集可能。
- **承認（申請）**: 申請フォームが5W1H入力（何を＝件名、いつ、どこで、誰が・誰と、どのように、なぜ＝理由※必須）になり、種別ごとの記入例を表示。承認者には5W1Hカードと完成度（n/6）を表示し、未記入の項目は「未記入」と強調（判断に必要なら差戻しで補足依頼）。一覧にも完成度バッジ。
- **出力**: 勤怠画面の「5W1Hの出力」から、月単位で **Notion用CSV**（Notionの *Import → CSV* でそのままデータベース化）、Markdown、印刷/PDF。監査用の出勤簿CSV・承認履歴CSVにも5W1H列を追加。
- **複数端末に即時反映**（サーバー版）: PCで入力するとスマホへ約1秒で反映（Server-Sent Events。切断時は60秒ごとに取得）。
- 行動メモは本人にしか見えません（管理者・監査でも不可。サーバー側で強制）。申請の5W1Hは申請後に変更できません（改ざん防止）。

> Notion API との直接の自動同期は未実装です（CSV/Markdown経由）。Supabase 等のクラウドDBへ載せ替える場合は `src/lib/store.tsx` の保存・取得部分と `src/server/` を差し替えます。

## 経理・会計・給与・監査（上場準備）

権限（`src/lib/perm.ts`）：一般社員／承認者／**経理担当**（E1004・E1013）／**監査**（E1005・読み取り専用）／全社管理者（E1002・E1006）。

| 画面 | 内容 |
|---|---|
| 決算書・販管費 | 損益計算書・貸借対照表・試算表・販管費（科目×月／部門別）・消費税、単位切替（円/千円/百万円）、月次締め、決算前チェック |
| 仕訳帳 | 借貸一致チェック、削除不可（取消は反対仕訳）、手動仕訳は**起票者以外**が承認、締め済み月は変更不可、電帳法の検索要件（日付・金額・取引先）、適格請求書の登録番号 |
| 給与 | 勤怠から時間外(1.25/60h超1.5)・深夜・休日を自動計算、社保・所得税(概算)・住民税、確定で仕訳自動作成、給与明細、一般社員は自分の確定済み明細のみ |
| 経費→仕訳 | 経費精算/出張が最終承認されると仕訳を自動作成（登録番号がなければ仕入税額控除しない） |
| 監査・税務調査出力 | 仕訳帳/総勘定元帳/試算表/給与台帳/出勤簿/承認履歴/監査ログをCSV(Excel対応)出力、**一括ZIP（MANIFEST＝各ファイルのSHA-256）**、印刷/PDF保存（出力者・日時つき帳票ヘッダー）。出力操作も監査ログに記録 |
| 上場準備 | J-SOX・決算・労務・ガバナンスのチェックリスト（データから自動判定＋手動）、上場基準の参考指標 |
| 監査ログ・管理 | ハッシュ連鎖による改ざん検知、サーバー認証ログ（ログイン失敗・ロック・権限拒否・IP） |

## セキュリティ設計（サーバーモード）

- 認証: scrypt パスワード、TOTP二要素（秘密鍵は AES-256-GCM で保存時暗号化）、5回失敗で15分ロック、IPレート制限、TOTPコードの再利用拒否、ログアウト/パスワード変更で全端末のセッション失効
- 認可: **サーバー側で**項目単位に強制（`src/server/policy.ts`）。一般社員のAPI応答に会計・他人の給与・他人の勤怠は含まれず、不正な書き込み（他人の打刻・承認の段階飛ばし・仕訳の改変/削除・締め済み月への計上・自己承認）は拒否してログに記録
- 監査: 操作ログと仕訳はハッシュ連鎖（削除・改変・並べ替えを検出）。監査ログはサーバーが連鎖を計算し、実行者は認証済み本人に固定
- ヘッダー: CSP・X-Frame-Options・nosniff・Referrer-Policy・COOP/CORP、CSRF（Origin検証）、Cookie は HttpOnly/SameSite=Lax（https では Secure）
- CSV: 数式インジェクション対策、Excel向けBOM付きUTF-8

### 限界（本番前に必要なこと）
- 保存先は `data/db.json`（単一サーバー・ファイル）。本番は PostgreSQL 等＋定期バックアップ＋保存時暗号化（KMS）、WORM/外部への監査ログ退避、SSO(SAML/OIDC)・SCIM連携を推奨
- 給与の料率・源泉徴収は概算（`src/lib/payroll.ts` 冒頭参照）。社労士・税理士の検証と最新の料率・税額表への更新が必要。賞与・年末調整・介護保険・36協定の特別条項管理・年金事務所/税務署への電子申請は未実装
- 会計は簡易版（単一法人・日本基準・円のみ・固定資産台帳/連結/キャッシュフロー計算書/株主資本等変動計算書なし）。決算書は監査法人・税理士の確認が前提
- 電子帳簿保存法・インボイス制度の最終的な要件充足は、税理士・所轄税務署に確認してください
- デモ版（GitHub Pages）は端末内保存・デモ認証のため、上記の**サーバー側の強制は働きません**（画面上の権限制御のみ）

## アイコンの自動生成

`npm run icons` が `scripts/gen-icons.mjs` の SVG から PWA / iOS / favicon 用の全サイズ（192・512・maskable・apple-touch）を生成します。ロゴを変えたいときは SVG を1か所直すだけです。

## 開発

```bash
npm run dev            # http://localhost:3000（開発中はサーバーモード）
npm run dev:lan        # LAN公開つき
npm run lint && npm run typecheck && npm test && npm run build
```

## 注意（サーバーモードの限界）

- 業務データ（申請・打刻など）は1つの共有DBファイルとして同期する簡易実装で、**サーバー側では項目ごとの権限検証をしていません**（認証済みの誰でも書き込み可）。本番化では API を機能ごとに分け、DB（PostgreSQL 等）と権限チェックを実装してください。
- 認証情報（パスワードハッシュ・TOTP秘密鍵）は `data/db.json` に平文JSONで保存されます（ファイル権限 600）。本番では暗号化・KMS を使ってください。
- 人物・会社・数値は全て架空です。
