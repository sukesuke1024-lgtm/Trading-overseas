# H-LINK 社内ポータル

H-LINK の社内ポータル（勤怠・申請承認・Excel連携・経理・監査）。
Next.js 16 + Tailwind v4。PC・スマホ（PWA）対応。ログイン + セキュリティコード（TOTP）、勤怠の自動計算つき。

## 前の版（Mirai HD 版）も使えます

公開サイトでは、今回の H-LINK 版が `/portal/`、前の版（5W1H削除後・コミット `682fa3e`）が `/portal-v1/` です。
手元で前の版を動かす場合: `git worktree add ../portal-v1 682fa3e && cd ../portal-v1/portal && npm ci && npm run dev`。

## 2つの動かし方

| モード | 認証 | データ | 用途 |
|---|---|---|---|
| **デモ（static）** | デモ認証（PIN固定・コード画面表示） | 各端末のブラウザ内 | GitHub Pages で公開・見せる用。`/portal/` で公開 |
| **サーバー（server）** | 従業員番号 + PIN（scrypt）+ 認証アプリのTOTP、5回失敗で15分ロック、CSRF対策、12時間セッション | サーバー上の `data/db.json`。PCとスマホで同期 | 社内LANで実際に使う |

### サーバーモード（同じネットワークのスマホからも勤怠を確認）

```bash
cd portal
npm install
npm run build
npm run start:lan        # 0.0.0.0 で待ち受け、LANのURLを表示（例: http://192.168.1.20:3000）
```

1. PCでもスマホでも、表示されたURLをブラウザで開く（同じWi-Fi/社内LAN）
2. 従業員番号（社長は `001`）と初期PIN（既定 `000000`。`PORTAL_INITIAL_PIN` で変更可）でログイン
3. 初回のみ QR を認証アプリ（Google/Microsoft Authenticator 等）で読み取り、6桁コードを入力
4. 初期PINの変更を求められます（4〜8桁の数字。連番・同じ数字の連続は不可）

外出先から使う場合は、社内VPN（または Tailscale 等）経由で同じURLに接続してください。**インターネットへ直接公開しないでください。**
ホーム画面へのインストール（PWA）は https が必要な端末があります（リバースプロキシで https 化）。

環境変数: `PORTAL_DATA_DIR`（データ保存先）, `PORTAL_INITIAL_PIN`, `PORTAL_SESSION_SECRET`（複数台構成時のみ）, `PORTAL_MAIL_WEBHOOK`（PIN再設定メールの送信API。下記）, `NEXT_PUBLIC_HELPDESK`（ログイン画面に出す問い合わせ先の表記）。

### デモ（GitHub Pages）

`main` へのマージで `.github/workflows/lp.yml` が LP と一緒にビルドし、`/portal/` に公開します（Settings → Pages → Source: GitHub Actions）。
手元で確認: `NEXT_PUBLIC_BASE_PATH= npm run build:static` → `out/`。ログイン画面に従業員番号とPIN、当日のデモ用コードが表示されます。

## 権限（3区分）

| 区分 | 勤怠 | 従業員マスタ | 申請・承認 | 経理・監査 | Excel連携 |
|---|---|---|---|---|---|
| **管理者**（社長＝長尾 晃佑 他） | 全員を閲覧・修正 | 取込・編集・権限設定 | 全件 | 編集可 | 可 |
| **役員** | 全員を閲覧のみ | 閲覧 | 全件 | 閲覧のみ | 不可 |
| **従業員** | 自分のみ入力・閲覧 | 氏名・職種のみ | 自分に関係する申請のみ | 不可 | 不可 |

権限は従業員マスタの「権限」で決まります（社長 001 は常に管理者・最後の管理者は降格不可）。サーバー側でも項目単位で強制します（`src/server/policy.ts`）。

## 勤怠 → Excel → 給与計算

1. 従業員が `/attendance` で日々の始業・終業・休憩を入力（所定 8:30〜17:00・休憩60分、25:00 のような翌日表記も可）。
2. 実労働・所定内・法定内/法定外残業・60h超・深夜・法定休日/法定外休日・休日深夜を、勤怠ブック（勤怠入力_自動計算.xlsx）と同じルールで自動計算（`src/lib/work.ts`）。
3. 管理者が `/excel` で
   - **勤怠ブックに反映**：従業員・休日マスタ・日別勤怠を書き込んだ xlsx をダウンロード（数式・書式はそのまま）
   - **賃金計算ブックに反映**：「⑤勤怠入力」の月・出勤〜フレックス繰越の列を書き込む。⑥賃金計算以降は Excel が自動計算
   - 日別勤怠・月次集計の CSV 出力
4. 従業員マスタは賃金計算ブック「④従業員マスタ」から取り込めます（番号・氏名・職種・雇用区分・所定時間などの**必要最小限だけ**。賃金額・マイナンバーは読みません）。

Excel ファイルは**ブラウザ内だけで処理**され、サーバーにもリポジトリにも保存されません（給与・マイナンバーを含むため）。
給与計算より先（振込・明細配布など）は未定です。

> 勤怠ブックの「深夜」列の式は、24:00〜29:00 を二重計上し、同日 0:00〜5:00 を拾えません。ポータルの計算は正しい値で、必要なら `/excel` の「深夜労働の計算式を修正する」で式を差し替えて出力できます。

## ログインとPINの再設定

ログインは **①従業員番号 → ②PIN（4〜8桁の数字）→ ③認証アプリのコード** の3段階です（IDとPINは別の画面）。ログアウト・無操作30分の自動ログアウトでログイン画面に戻ります。PINは5回間違えると15分ロックされます。

ログイン画面の「ログインできない・PINをお忘れの方はこちら」から：
1. **メールで再設定**：従業員番号と登録済みの会社メールを送信 → 15分有効・1回限りの再設定URLをメールで送付 → 新しいPINを設定。登録の有無は画面に出しません。再設定しても認証アプリのコードは必要です（メールだけでは入れません）。
2. **管理者へ申請**：メールが届かない・未登録・認証アプリ紛失のとき。管理者が「従業員・権限」の「PINリセット申請」で本人確認のうえ、再設定URLを発行して直接伝える／初期PINに戻す。

メールアドレスは管理者が「従業員・権限」の編集で登録します（賃金計算ブックには無い項目です）。**メール送信は `PORTAL_MAIL_WEBHOOK`（JSONで `{to, subject, text}` をPOSTできる社内のメール送信API等。任意で `PORTAL_MAIL_TOKEN`）を設定したときに動きます。** 未設定の間は送信されず（`data/outbox.jsonl` に記録のみ）、管理者画面に警告が出ます。その場合は「管理者へ申請」の運用で対応できます。

## 業務機能

| 画面 | 内容 | 権限 |
|---|---|---|
| 業務カレンダー | 全社共通の予定を日・週・月で表示（祝日は休日マスタと連動） | 全員が閲覧／予定の登録は役員・管理者 |
| 業務日報 | 業務・明日の予定・課題。提出後に役員・管理者がコメント。出勤して未提出の人を一覧 | 本人／全員分は役員・管理者 |
| KPI管理 | 月ごとの目標と実績、達成率。担当者は自分のKPIの実績を入力 | 管理者が定義／従業員は全社＋自分の分 |
| 経費精算・決裁（稟議書） | 申請・承認ワークフロー（種別ごとの一覧と新規申請）。経費は最終承認で仕訳を自動作成 | 全員が申請 |
| 有給管理 | 入社日から法定の付与日数・繰越・取得（勤怠の「有給休暇」から自動集計）・残日数・年5日取得義務のアラート。付与日数は手入力で上書き可 | 本人／全員分は役員・管理者 |
| 文書管理・社内規程 | 規程・マニュアルの登録、版管理、「確認しました」の既読 | 全員が閲覧・確認／登録は管理者 |
| 従業員名簿・組織図 | 組織図（上司の設定による階層）、部署別、名簿 | 全員（連絡先・メール等の詳細は役員・管理者） |
| リモート接続 | 社内PC等への接続先一覧。RDPは .rdp ファイルをダウンロード、VNC/SSH/Webはリンク。接続は監査ログに記録 | 従業員は自分に割り当てられた分のみ |
| お知らせ | 全社・慶弔・新入社員・人事など | 投稿は管理者 |

ホームのウィジェットは、一般社員と役職者（役員・管理者）で初期の構成が異なり、「ウィジェットの設定」で表示・並び順を変えられます（端末ごとに保存）。
リモート接続は画面を中継するものではなく、端末のリモートデスクトップを起動する入口です。社内VPN経由でご利用ください。

## 画面

ホーム（今日の打刻・ToDo）／勤怠／申請・承認／お知らせ／従業員・権限／Excel連携・CSV／決算書・販管費／仕訳帳／監査・税務調査出力／上場準備／監査ログ。

## 複数端末への即時反映（サーバー版）

PC で入力した内容がスマホへ約1秒で反映されます（Server-Sent Events）。デモ版はブラウザ内保存のため対象外です。

## セキュリティ設計（サーバーモード）

- 認証: scrypt ハッシュのPIN、TOTP二要素（秘密鍵は AES-256-GCM で保存時暗号化）、5回失敗で15分ロック、IPレート制限、TOTPコードの再利用拒否、ログアウト/PIN変更・再設定で全端末のセッション失効
- 認可: **サーバー側で**項目単位に強制（`src/server/policy.ts`）。一般社員のAPI応答に会計・他人の給与・他人の勤怠は含まれず、不正な書き込み（他人の打刻・承認の段階飛ばし・仕訳の改変/削除・締め済み月への計上・自己承認）は拒否してログに記録
- 監査: 操作ログと仕訳はハッシュ連鎖（削除・改変・並べ替えを検出）。監査ログはサーバーが連鎖を計算し、実行者は認証済み本人に固定
- ヘッダー: CSP・X-Frame-Options・nosniff・Referrer-Policy・COOP/CORP、CSRF（Origin検証）、Cookie は HttpOnly/SameSite=Lax（https では Secure）
- CSV: 数式インジェクション対策、Excel向けBOM付きUTF-8

### 限界（本番前に必要なこと）
- 保存先は `data/db.json`（単一サーバー・ファイル）。本番は DB＋定期バックアップ＋監査ログの外部退避、SSO 連携を推奨
- 給与計算そのものは Excel（賃金計算ブック）側で行い、ポータルは⑤勤怠入力までを自動反映します。共有フォルダへの自動同期は未実装
- 会計は簡易版（単一法人・日本基準・円のみ）。決算書は税理士・監査法人の確認が前提
- デモ版（GitHub Pages）は端末内保存・デモ認証（初期PIN `135790`、画面にコード表示。再設定メールの代わりに画面にリンクを表示）のため、サーバー側の権限強制は働きません

## ロゴ・アイコンの自動生成

## 開発

```bash
npm run dev            # http://localhost:3000（開発中はサーバーモード）
npm run dev:lan        # LAN公開つき
npm run lint && npm run typecheck && npm test && npm run build
```

人物・数値のサンプルは架空です（社長名と社名のみ実在）。
